# DM ページ 実装プラン

DM ページを AI 主導で実装するにあたり、人間と AI の間で「何をどの順番で作るか」の認識を揃えるための文書。

## 前提

- ツイートページ・リプライページは手で実装済み。DM ページは同じ型の 3 回目になるため、AI に実装させて人間がレビューする形で進める。
- 1 つの PR で DM ページ全体を作らず、機能ごとにフェーズを分ける。1 フェーズ = 1 PR。
- 層（テンプレート / サーバー）で分けるのではなく、機能で分ける。各フェーズは「動かして確認できる状態」で終わらせる。
- 取得機能を最初に作る。admin からテストデータを手で入れる手間をなくし、以降のフェーズを実データで確認するため。
- 画面構成は `docs/design/screen-map.pdf` の 2-3 に従う（左に会話一覧、右にスレッド）。
- DB は `docs/design/databese.md` の Conversation / DirectMessage / DirectMessageMedia を使う。モデルとマイグレーションは作成済み。
- 既存の tweets アプリと同じ構成にする。view → X API → DB 保存 → 部分テンプレートを `render_to_string()` して JSON で返し、jQuery で差し替える。

## フェーズ一覧

| フェーズ | 内容                                   | 規模 |
| -------- | -------------------------------------- | ---- |
| 1        | ページヘッダーと「DM取得」ボタンの作成 | 大   |
| 2        | 取得した DM の表示機能の作成           | 中   |
| 3        | DM 返信機能の作成                      | 中   |

## フェーズ 1：ページヘッダーと「DM取得」ボタンの作成

### 目的

X API から DM を取得して DB に保存できるようにする。

### 含める作業

- `dm.html` にページヘッダー（見出しと「DM取得」ボタン）を作る。ツイートページ・リプライページと同じ見た目にする。
- 取得確認モーダル（料金の注意書きと「取得」ボタン）を作る。
- `common/x_api.py` に DM 取得用のエンドポイント定数を追加する。
- `common/x_api_client.py` に DM 取得リクエストの関数を追加する。
- `dm/models.py` の各 Manager に、レスポンスから Conversation / DirectMessage / DirectMessageMedia を保存する処理を追加する。
- DM の相手を XUser として保存する処理を追加する。既存の `XUserManager.not_saved_author_ids()` はツイートのレスポンス用なので、DM のレスポンスに対応したものが必要。
- 取得 view と URL を追加する。既存の `save_all_tweets` / `save_all_replies` と同じ流れにする。
- ボタン押下から view を呼ぶ JS を追加する。成功時はトーストを出す。

### 含めない作業

- 取得した DM の画面表示（フェーズ 2）。
- DM の送信（フェーズ 3）。

### 完了条件

- 「DM取得」ボタンを押すと、X API から DM が取得され、DB に保存される。
- admin で Conversation / DirectMessage / DirectMessageMedia / XUser のレコードが確認できる。
- 通信失敗・401・想定外ステータスの場合に、既存ページと同じエラー表示になる。

### 決めたこと

- **エンドポイント**：`GET /2/dm_events` を使う。自分が参加している DM を新しい順に返す。取得できるのは直近 30 日分のみ。
- **取得の打ち切り**：DM は新しい順に返るため、保存済みの DM が含まれるページまで取得したら打ち切る。
- **1 回目の取得件数**：まず 20 件だけ取得する。X API は取得件数で課金され、UTC の日付が変わると保存済みの DM にも再度課金されるため、毎回 100 件取得すると新着が少なくても料金がかさむ。
- **新着が多い場合**：20 件の中に保存済みの DM がなければ、最初から 100 件ずつ取得し直す。同じ UTC の日付内に同じ DM を取得しても再度課金されないため、取り直した分の料金はかからない。100 件にしているのは、リクエスト回数の上限が 15 分に 15 回のため。
- **保存済みの除外**：DM・メディアは ID で保存済みかを判定し、未保存のものだけ保存する。会話は `dm_conversation_id` で判定し、保存済みの場合は最後のメッセージ日時だけ更新する。
- **グループ DM**：`dm_conversation_id` に `-` を含まないものはグループ DM なので保存しない。
- **会話相手**：`dm_conversation_id`（小さいユーザーID-大きいユーザーID）から相手の ID を取り出し、未保存なら `GET /2/users` で取得して保存する。凍結などで取得できなかった相手は、会話相手・送信者を空にして保存する。
- **30 日より前の DM**：保存されている最新の DM が 30 日より前の場合は、取得できていない DM がある可能性をトーストで伝える。リプライ取得の 7 日制限と同じ扱い。
- **モデルの変更**：動画の DM は X API が `url` を返さないため、`DirectMessageMedia` の `url`・`width`・`height` を `TweetMedia` と同じく空を許可する。

## フェーズ 2：取得した DM の表示機能の作成

### 目的

DB に保存された DM を、会話一覧とスレッドの 2 ペインで表示できるようにする。

### 含める作業

- `dm_view` で Conversation と DirectMessage を DB から読んでテンプレートに渡す。Manager に取得用のメソッドを追加する。
- 左ペインに会話一覧を表示する。相手のアイコン・名前・最終メッセージを出す。
- 右ペインに選択中の会話のスレッドを表示する。自分の発言と相手の発言を左右に分けて出す。
- 会話一覧をクリックするとスレッドが切り替わる JS を追加する。
- フェーズ 1 の取得完了後に、一覧とスレッドが差し替わるようにする。
- 部分テンプレートに分ける（会話一覧・スレッド・メッセージ 1 件など）。

### 含めない作業

- DM の送信（フェーズ 3）。

### 完了条件

- フェーズ 1 で保存した DM が、会話一覧とスレッドに表示される。
- 会話を切り替えるとスレッドの内容が変わる。
- 「DM取得」後に画面が更新される。

### 決めたこと

- **会話一覧の並び順**：最後のメッセージが新しい順。メッセージが 1 件もない会話は一番下にする。
- **スレッドの並び順**：古い順。一番下が最新で、開いた時は一番下までスクロールする。
- **スレッドの切り替え**：全会話のスレッドをサーバー側で描画しておき、JS で表示を切り替える。DM は DB から読むだけで料金がかからず、件数も多くないため、ページ遷移や追加のリクエストは不要。
- **初期表示**：一番上の会話を開く。DM 取得のあとは、開いていた会話が残っていればそれを開き直す。
- **DM 取得後の更新**：会話一覧とスレッドをまとめた `_dm_body.html` を返し、JS で差し替える。
- **メディアの表示**：吹き出しの中に画像を並べ、クリックで拡大する。拡大用のモーダルは tweets と共通のため、`templates/_image_modal.html` に移動して両方から読み込む。
- **動画の表示**：X API は動画の `url` を返さないため、「動画は表示できません」と出す。
- **本文の t.co リンク**：メディアが付いている DM のみ、本文末尾の t.co リンクを取り除く。メディアがない DM は、本文中のリンクを消さないためそのまま表示する。
- **日時の表示**：会話一覧は当日なら「14:31」、それ以外は日付。スレッドは日付ごとに区切りを入れ、各 DM には「14:31」を出す。
- **相手の情報がない場合**：凍結などで会話相手や送信者が空の場合は、アイコンを灰色の丸にして「ユーザー情報なし」と出す。

## フェーズ 3：DM 返信機能の作成

### 目的

スレッドから DM を送信できるようにする。

### 含める作業

- スレッド下部に入力欄と送信ボタンを作る。
- `common/x_api.py` と `common/x_api_client.py` に DM 送信用の定数と関数を追加する。
- 送信 view と URL を追加する。既存の `post_reply` と同じ流れにする。
- 送信した DM を DB に保存し、スレッドに追加する。
- 送信ボタン押下から view を呼ぶ JS を追加する。

### 含めない作業

- 新規の相手への DM 開始。既存の会話への返信のみ。

### 完了条件

- スレッドから DM を送信すると、X 側に届き、DB に保存され、スレッドに表示される。
- 通信失敗・401・想定外ステータスの場合に、既存ページと同じエラー表示になる。

### 決めたこと

- **エンドポイント**：`POST /2/dm_conversations/{dm_conversation_id}/messages` を使う。成功時のステータスコードは 201。
- **送信後の保存**：手元の値から保存する。送信のレスポンスに入るのは会話 ID と DM の ID だけで、本文も送信日時も返らない。DM には 1 件だけ取得するエンドポイントがないため、取り直すと別途料金がかかる。送信日時は保存した時刻を使う。
- **画像添付**：対応しない。画面設計にも入っていない。対応する場合は、アップロード時のカテゴリを DM 用にする必要があり、メディアの情報を得るために取り直しの料金もかかる。
- **文字数**：カウンターは出さず、空欄だけ弾く。上限は X 側の判断に任せ、超えた場合はエラーとして表示する。
- **送信後の画面更新**：DM 取得と同じく `_dm_body.html` を返して差し替える。会話一覧の最後のメッセージと並び順も一緒に更新されるため。
- **送信先の会話がない場合**：会話が見つからない場合は X API を呼ばずにエラーを返す。
