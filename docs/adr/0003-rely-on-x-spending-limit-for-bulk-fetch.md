# 0003. リプライ・DM の大量取得による料金を X の利用料金の上限で制御する

**ステータス**: 採用（2026-09-17）

## 背景

リプライと DM の取得は、X API から取得した件数に応じて料金がかかるため、
大量にリプライなどが付くと取得時に大量の料金がかかる可能性がある。

- リプライの取得は `since_id` で「保存済みの最新のリプライより新しいもの」に絞れるが、
  その範囲に大量のリプライがあれば全件取得することになる。
- DM の取得には「この DM より新しいもの」に絞る方法がない。新しい順に取得し、
  保存済みの DM が出てきたところで打ち切っている。

プログラム側で大量の取得を防ごうとしても、次の問題がある。

- 取得する前に、未取得のリプライ・DM が何件あるか分からない。大量に付いていることに気づけるのは、
  実際に取得して料金がかかったあとになる。
- プログラム側でできるのは、決まった件数を取得したところで打ち切ることだけになる。
  ただし、リプライも DM も新しい順に取得するため、途中で打ち切って保存すると、古い側の未取得分が
  取得されないまま残る。次の取得は保存済みの最新のもので打ち切られるため、あとから取得する方法がない。
- 打ち切った分を保存しない場合は、やり直しても毎回同じ所で止まり、取得が完了しない。

## 決定

- 大量のリプライ・DM が付いた場合は考慮せず、取得できた分をすべて保存する。
- 料金は、X Developer Portal で設定している API 利用料金の上限で制御する。
- 上限に達した場合は、状況に応じて次のいずれかで自分で対応する。
  - 利用料金の上限を上げる
  - クレジットを追加する
  - DM を閉鎖する

## 理由

- 取得する前に件数が分からないため、料金がかかる前に大量の取得を防ぐことはできない。
- プログラム側で打ち切る方法では、取得漏れや取得が完了しない問題が起きる。
- 個人利用であり、現時点で大量のリプライ・DM は付いていない。起きていない問題のために
  取得処理を複雑にするより、X 側の上限で止めるほうが単純で確実。
- X 側で上限を設定しているため、想定外に大量の料金がかかることはない。

## 影響

- 上限に達すると、データの取得だけでなく、ツイートやリプライの投稿も含めて
  X API を使うすべての機能が止まる。
- 上限に達した場合も、画面には「想定外のエラーが発生しました。」とエラーコードが表示されるだけで、
  料金の上限が原因だとすぐには分からない。エラーが続く場合は X Developer Portal で利用状況を確認する。
